What is OmniRID?

OmniRID is an open-source firmware being developed to transform any ESP32 microcontroller into a universal Remote ID transmitter targeting ASTM F3411-22a (USA) and ASD-STAN prEN 4709-002 (EU) standards. It is designed to read GPS position data from a flight controller via UART and broadcast ASTM-standard Open Drone ID messages over WiFi Beacon (802.11) and Bluetooth Low Energy (BLE 4.0 and BLE 5.0 Coded PHY).

⚠ Development Status: The firmware code is feature-complete for v1.0.0-beta. All 21 ESPsquawk fork security and functionality fixes have been ported. A built-in demo mode simulates a GPS patrol over Rome (Colosseum) so you can test the full config UI, OTA flow, and telemetry dashboard without flight controller hardware. Actual flight controller (FC) hardware verification with MAVLink/MSP/NMEA is ongoing. See the software status for the complete per-file analysis.

Implemented Features

  • Triple protocol input: MAVLink (ArduPilot), MSP (Betaflight/iNAV), NMEA 0183 parsers
  • Automatic protocol detection on boot — no manual switching needed
  • Dual radio broadcast: WiFi Beacon (802.11) + WiFi NAN + BLE 4.0 + BLE 5.0 Long Range Coded PHY (dual instances)
  • Built-in demo mode — GPS patrol simulation for testing without FC hardware
  • Built-in WiFi Access Point with web configuration at 192.168.4.1
  • Over-the-Air (OTA) updates with client-side SHA-256 + Ed25519 signature verification
  • Security hardening: JSON parsing (serde), rate limiting (10 fails/60s), safe string handling, PSA Crypto init
  • Shared security module: rid-core::security for SHA-256 + Ed25519 verification
  • Takeoff location capture: first 3D GPS fix stored as operator reference position
  • Security lock levels: level 0 (open), level 1 (Ed25519 signed commands), level 2 (eFuse permanent)
  • eFuse permanent lock: one-time irreversible level 2 burn with "RID!" magic
  • 70+ configurable parameters via web UI (identity, transmission, WiFi AP, serial, lighting, DroneCAN, security)
  • Browser-based flashing via WebSerial — no toolchain needed
  • 3 ESP32 targets via CI: ESP32, ESP32-S3, ESP32-C6
  • WS2812 addressable RGB LED — RMT-driven with configurable GPIO and brightness
  • 5 independent GPIO lighting outputs — 6 patterns (OFF, SOLID, BLINK_SLOW, BLINK_FAST, ARMED, GPS_FLASH) with phase offset per channel
  • DroneCAN (CAN Bus) — TWAI driver, configurable RX/TX GPIOs, 1 Mbps default bitrate
  • MAVLink USB transport — bidirectional MAVLink over USB CDC (S3/C6)
  • Configurable UART port, TX and RX pins — select any GPIO for serial data
  • OTA trigger GPIO — boot-time GPIO to enter OTA update mode
  • Configurable startup delay — delay transmission start up to 30 s
  • 1D × 3 Kalman position filter — smooths lat/lon/alt with 3 s timeout
  • Ed25519 authentication pages — ASTM F3411-22a signed authentication
  • 9 option bits — force ARM, no save BasicID, print MAVLink RID, demo mode, Kalman filter, Ed25519 auth, MAVLink arm status, MAVLink op loc loopback, identity ready gate

Regulatory Compliance

The firmware targets the ASTM F3411-22a Open Drone ID (ODID) message set. The following message types are implemented in code:

  • Basic ID Message — UAS ID, ID type, UA type
  • Location/Vector Message — latitude, longitude, altitude, speed, heading
  • System Message — operator ID, timestamps
  • Self-ID Message — additional operator information

Note: Compliance with FAA Part 89, EASA 2021/664, or any other regulation has not been certified. Regulatory validation with certified receivers is required before use in actual flight operations.

Power Options

  • From FC BEC: Connect to the 5V pad on your flight controller's servo rail or BEC output. Most BECs provide 5V @ 2-3A, sufficient for the ESP32 (~150 mA).
  • From USB: Power via the ESP32's USB port during configuration and testing.
  • From battery: Use a 5V step-down regulator (e.g. Matek 5V bec) connected to the main battery.

The ESP32 draws approximately 150 mA with WiFi Beacon + BLE active. Ensure your BEC or regulator can supply this.

Antenna Selection

⚠ Important: Carbon fiber drone frames are conductive and will severely attenuate the ESP32's built-in PCB antenna. Use a board with a U.FL/IPEX connector for an external antenna.
  • PCB antenna: Suitable for glass fiber, plastic, or open frames. Range ~50-100 m.
  • External antenna (U.FL): Required for carbon fiber frames. Range ~200-500 m with 2 dBi antenna.
  • Recommended: ESP32-S3-DevKitC-1 with U.FL, or TTGO T-Internet-POE with external antenna.

Voltage Levels

The ESP32 GPIO pins are 5V tolerant but the UART RX pin (GPIO16) uses 3.3V logic levels. Most flight controllers use 3.3V UART (Pixhawk, Matek, Betaflight boards). If your FC uses 5V UART (some older ArduPilot boards), use a level shifter or a voltage divider (1 kΩ + 2.2 kΩ) on the RX line.
